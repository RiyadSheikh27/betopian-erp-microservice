## Architecture

```
Client
  │
  ├─► Nginx (:80 / :443) ──► Daphne web container (:8000)
  │                              ├─► PostgreSQL (db)
  │                              ├─► Redis
  │                              └─► S3 (Zenex Cloud)
  │
  └─► Coturn (:3478 / :5349 / 49152–65535)   [host network, not proxied]
```

| Service | What it does | Port |
|---|---|---|
| `web` (Daphne) | Django ASGI server | `8000` (public during testing, then internal via Nginx) |
| `db` (PostgreSQL 16) | Main database | `5432` (internal) |
| `redis` (Redis 7) | Channel layer for Django Channels | `6379` (internal) |
| `coturn` | TURN/STUN server for WebRTC | `3478`, `5349`, `49152–65535` |
| Nginx | Reverse proxy + SSL termination | `80`, `443` (public) |

On container start, `web` automatically runs migrations, `collectstatic`, then Daphne.

## Domain & SSL Setup

Complete the IP-phase tests above before proceeding.

### Step 1 — DNS records

Add **both** records at your DNS provider:

| Type | Name / Host | Value |
|---|---|---|
| A | `social-media` | `103.161.9.10` |
| A | `www.social-media` | `103.161.9.10` |

Or use a CNAME for `www`:

| Type | Name / Host | Value |
|---|---|---|
| CNAME | `www.social-media` | `social-media.betopiagroup.com` |

Verify propagation:

```bash
dig +short social-media.betopiagroup.com
dig +short www.social-media.betopiagroup.com
# Both should return: 103.161.9.10
```

> Certbot will fail with `NXDOMAIN` if the `www` record is missing.

### Step 2 — Install Nginx

Nginx is **not** included in Docker — install it on the host:

```bash
sudo apt update
sudo apt install -y nginx
nginx -v
sudo systemctl enable nginx
sudo systemctl start nginx
```

### Step 3 — Create Nginx site config

```bash
sudo nano /etc/nginx/sites-available/betopian-erp
```

```nginx
upstream daphne {
    server 127.0.0.1:8000;
}

server {
    listen 80;
    server_name social-media.betopiagroup.com www.social-media.betopiagroup.com 103.161.9.10;
    client_max_body_size 200M;

    location /static/ {
        alias /home/betopia/betopian-erp-microservice/staticfiles/;
    }

    location / {
        proxy_pass http://daphne;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}
```

Enable and test:

```bash
sudo ln -sf /etc/nginx/sites-available/betopian-erp /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

Verify HTTP works **before** requesting SSL:

```bash
curl -I http://103.161.9.10/api/schema/
curl -I http://social-media.betopiagroup.com/api/schema/
# Expect: HTTP/1.1 200
```

WebSockets through Nginx (no `:8000`):

```
ws://social-media.betopiagroup.com/ws/notifications/?token=<access_token>
```

### Step 4 — SSL with Certbot

```bash
sudo apt install -y certbot python3-certbot-nginx

sudo certbot --nginx \
  -d social-media.betopiagroup.com \
  -d www.social-media.betopiagroup.com
```

Provide a valid email when prompted. Choose redirect HTTP → HTTPS when asked.

If `www` DNS is not ready yet, issue a cert for the apex only:

```bash
sudo certbot --nginx -d social-media.betopiagroup.com
```

### Step 5 — Update `.env` for production domain

```bash
nano ~/betopian-erp-microservice/.env
```

```env
DEBUG=False
ALLOWED_HOSTS=social-media.betopiagroup.com,www.social-media.betopiagroup.com,103.161.9.10
TURN_HOST=social-media.betopiagroup.com
```

Keep `external-ip=103.161.9.10` in `coturn/turnserver.conf` — do **not** change it to the hostname.

### Step 6 — Restart services

```bash
cd ~/betopian-erp-microservice
docker compose up -d web
docker compose restart coturn
sudo systemctl reload nginx
```

### Step 7 — Verify HTTPS

```bash
curl -I https://social-media.betopiagroup.com/api/schema/
curl -H "Authorization: Bearer <token>" \
  https://social-media.betopiagroup.com/api/v1/turn-credentials/
```

Expected TURN URLs from the API:

```
stun:social-media.betopiagroup.com:3478
turn:social-media.betopiagroup.com:3478?transport=udp
turn:social-media.betopiagroup.com:3478?transport=tcp
turns:social-media.betopiagroup.com:5349?transport=tcp
```

### Step 8 — Harden (optional)

Once Nginx + HTTPS work, close direct port 8000:

```bash
sudo ufw delete allow 8000/tcp
```

## TURN Server (Coturn)

Config file: `/home/betopia/betopian-erp-microservice/coturn/turnserver.conf`

- Runs in `network_mode: host` — binds directly on VPS ports (not Docker NAT)
- `external-ip` = `103.161.9.10` (always the real public IP)

- `static-auth-secret` must match `TURN_SECRET` in `.env`

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `No such file or directory` saving Nginx config | Nginx not installed | `sudo apt install -y nginx` |
| Certbot `NXDOMAIN` for `www` | Missing DNS record | Add A record for `www.social-media` |
| `curl` returns nothing on port 80 | Nginx not running or misconfigured | `sudo systemctl status nginx`, `sudo nginx -t` |
| `502 Bad Gateway` | Web container down | `docker compose ps`, `docker compose logs web` |
| `DisallowedHost` | Wrong `ALLOWED_HOSTS` | Update `.env`, `docker compose up -d web` |
| WebSockets fail over HTTPS | Missing upgrade headers | Check Nginx `Upgrade` / `Connection` headers |
| Calls fail, REST works | Coturn ports blocked or `TURN_HOST` wrong | Check firewall + `.env` + coturn secret match |
| Permission denied editing `/etc/nginx/...` | Missing `sudo` | Use `sudo nano /etc/nginx/...` |
