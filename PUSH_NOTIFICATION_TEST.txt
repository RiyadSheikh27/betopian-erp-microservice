Chat Push Notification — Terminal Test Guide
=============================================

Prerequisites
-------------
1. Server running (e.g. python manage.py runserver or daphne)
2. FIREBASE_CREDENTIALS_PATH set in .env pointing to firebase service account JSON
3. Two user accounts (sender + recipient) with valid Microsoft tokens
4. Recipient must login WITH fcm_token so the server can push when app is backgrounded

Variables (set these in your shell)
-----------------------------------
BASE=http://localhost:8000/api/v1
MS_TOKEN_RECIPIENT=<microsoft_access_token_for_recipient>
MS_TOKEN_SENDER=<microsoft_access_token_for_sender>
FCM_TOKEN=<real_firebase_token_from_flutter_or_firebase_console>
DEVICE_ID=my-test-phone-001


Step 1 — Recipient login (registers device for push)
------------------------------------------------------
curl -s -X POST "$BASE/login/" \
  -H "Content-Type: application/json" \
  -d "{
    \"access_token\": \"$MS_TOKEN_RECIPIENT\",
    \"appVersion\": \"1.0.0\",
    \"deviceId\": \"$DEVICE_ID\",
    \"fcm_token\": \"$FCM_TOKEN\",
    \"platform\": \"android\"
  }" | jq .

Save from response:
  RECIPIENT_JWT  = data.access_token
  RECIPIENT_ID   = data.user.id


Step 2 — Sender login (no fcm_token needed for sending)
-------------------------------------------------------
curl -s -X POST "$BASE/login/" \
  -H "Content-Type: application/json" \
  -d "{
    \"access_token\": \"$MS_TOKEN_SENDER\",
    \"appVersion\": \"1.0.0\",
    \"deviceId\": \"sender-device\"
  }" | jq .

Save from response:
  SENDER_JWT = data.access_token
  SENDER_ID  = data.user.id


Step 3 — Start DM (sender creates conversation with recipient)
--------------------------------------------------------------
curl -s -X POST "$BASE/conversations/" \
  -H "Authorization: Bearer $SENDER_JWT" \
  -H "Content-Type: application/json" \
  -d "{\"user_id\": \"$RECIPIENT_ID\"}" | jq .

Save from response:
  CONV_ID = data.id


Step 4 — Send text message via WebSocket (triggers FCM to recipient)
--------------------------------------------------------------------
Install wscat if needed: npm install -g wscat

wscat -c "ws://localhost:8000/ws/chat/$CONV_ID/?token=$SENDER_JWT"

Then type and send:
{"type":"message","body":"Hello from terminal test!"}

Expected:
  - Sender sees echo: {"type":"message","data":{...}}
  - Recipient phone gets FCM if app is in background
  - Server log: FCM sent | user=<recipient_id> success=1 failure=0


Step 5 — Verify device token stored (Django shell)
--------------------------------------------------
python manage.py shell -c "
from apps.notifications.models import DeviceToken
for t in DeviceToken.objects.all():
    print(t.user.email, t.device_id, t.platform, t.fcm_token[:20]+'...')
"


Step 6 — Logout recipient (optional, removes push token)
--------------------------------------------------------
curl -s -X DELETE "$BASE/devices/unregister/" \
  -H "Authorization: Bearer $RECIPIENT_JWT" \
  -H "Content-Type: application/json" \
  -d "{\"device_id\": \"$DEVICE_ID\"}" | jq .


Notes
-----
- Login WITHOUT fcm_token still works; user just won't receive push until they login with push fields.
- FCM token refresh: login again with the new fcm_token (same deviceId).
- Postman/curl cannot receive FCM — test push on a real phone with Flutter app in background.
- Chat push is automatic on new message; no separate register API.

Login body reference
--------------------
{
  "access_token": "<microsoft_token>",
  "appVersion": "1.0.0",
  "deviceId": "stable-device-uuid",
  "fcm_token": "firebase-token",
  "platform": "android"
}

FCM data payload (what the app receives)
----------------------------------------
{
  "type": "chat_message",
  "conv_id": "<conversation-uuid>",
  "message_id": "<message-uuid>",
  "payload": "<stringified message json>"
}
